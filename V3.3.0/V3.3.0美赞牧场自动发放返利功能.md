### [M2] 扫码出库：新增「返利发放 / 返利发放状态 / 失败原因」字段（覆盖列表查询、订单详情、导出）
- **修改页面**：PC 后台 → 运营中心 → 美赞牧场 → 扫码配置 → 扫码出库
- **修改点（产品经理需求）**：
  1. **订单详情 - 返利发放**：新增字段「返利发放」，展示值=自动发放 / 人工发放。
     - 1.1 活动类型=NUA活动 → 默认展示「人工发放」。
     - 1.2 活动类型=NSA活动，且生成订单时当前 NSA配额规则「自动发放返利=是」→ 展示「自动发放」。
     - 1.3 活动类型=NSA活动，且生成订单时当前 NSA配额规则「自动发放返利=否」→ 展示「人工发放」。
  2. **订单详情 - 返利发放状态**：新增字段「返利发放状态」，取值=待发放 / 发放中 / 已发放 / 发放失败。
     - 2.1 返利发放=人工发放 → 不展示该状态字段。
     - 2.2 返利发放=自动发放：NSA订单审核通过后，次日凌晨调 CMP 平台二次确认接口查询是否满足发放条件——
       - 2.2.1 尚未到次日调 CMP 接口 → 状态默认「待发放」。
       - 2.2.2 次日调 CMP 接口且满足发放条件 → 由返利导入生成返利任务（逻辑见返利导入单独说明），返利任务状态=待执行，返利状态=「发放中」。
       - 2.2.3 返利导入对应返利任务状态=已执行 → 返利状态=「已发放」。
       - 2.2.4 次日调 CMP 接口返回不满足发放条件 → 返利状态=「发放失败」，同时新增字段「失败原因」展示具体数据。
  3. **查询条件**：
     - 3.1 新增「发放方式」下拉，默认全部，可选：自动发放 / 人工发放。
     - 3.2 新增「返利状态」下拉，默认全部，可选：待发放 / 发放中 / 已发放 / 发放失败。
  4. **导出**：导出增加字段——返利发放、返利状态、失败原因。
- **原型改动（HTML 位置/字段）**：文件 `V3.3.0美赞牧场自动发放返利功能.html`
  - 列表筛选（扫码出库 `.filters`，约 L940–946）：新增 Filter Row 4，含「发放方式」「返利状态」两个下拉（默认「全部」）。
  - 订单详情基本信息区（约 L1054–1056）：新增三个信息单元——
    - 「返利发放」（id `qc-info-rebateIssue`，始终展示）；
    - 「返利发放状态」（id `qc-cell-issueStatus` / `qc-info-rebateIssueStatus`，仅自动发放时展示）；
    - 「失败原因」（id `qc-cell-failReason` / `qc-info-failReason`，仅发放失败时展示）。
  - 详情 JS 逻辑（约 L1605–1631，`onViewQc` 内）：依据 `activityType` 与当前 NSA配额规则「自动发放返利」计算「返利发放」；自动发放时按 demo 数据展示「返利发放状态」，人工发放隐藏状态与失败原因，发放失败时展示失败原因。
  - 演示数据覆盖（约 L1489–1494）：4 条 NSA 订单分别演示 发放中 / 已发放 / 待发放 / 发放失败(+失败原因)，1 条订单改为 NUA活动 演示「人工发放」（状态隐藏）。
  - 导出按钮（约 L953）：补充 `title` 标注导出字段含 返利发放 / 返利状态 / 失败原因（与后端导出字段对齐）。
  - 说明：列表表格列**未新增**（需求仅要求详情、查询、导出三处），保持原 13 列不变。

### [M3] 返利导入：新增「返利类型」字段 + 美赞牧场自动任务 + 新增任务入口 + 返利预警
- **修改页面**：PC 后台 → 分销中心 → 分销运营 → 返利导入
- **修改点（产品经理需求）**：
  1. 列表新增字段「返利类型」（紧邻任务编号之后），取值 = 人工调整 / 美赞牧场。
     - 1.1 手动新增任务（走新增任务入口）→ 返利类型默认 = 人工调整。
     - 1.2 系统满足美赞牧场条件时自动新增的任务 → 返利类型默认 = 美赞牧场。
  2. 返利类型 = 美赞牧场 的数据来源与规则：
     - 2.1 数据来源：美赞牧场 NSA 订单的返利；按「天」维度每天生成一条任务编号；每条任务明细 = 运营中心 - 美赞牧场 - 扫码出库，活动类型 = NSA活动，返利发放 = 自动发放，取当天凌晨调 CMP 接口满足发放条件的全部订单明细。
     - 2.2 返利名目展示：出库订单 + 美赞牧场。
     - 2.3 门店ID / 门店名称：出库订单为总店 → 直接发放给总店，展示总店信息；出库订单为分店 → 发放给分店关联的总店，展示总店信息（即无论总/分店，列表与明细均展示总店信息）。
     - 2.4 导入金额：出库订单的返利金额。
  3. 列表 - 返利类型 = 美赞牧场 且 返利状态 = 待执行 时，操作列仅展示「执行」按钮：支持人工点击执行（同原逻辑），也支持隔 X 小时后系统自动执行（X 由开发配置，后续统一提供）。
  4. 新增「返利预警」：返利类型 = 美赞牧场 且 导入金额 > Y 元时，向指定邮箱发送邮件（导入金额阈值 Y、通知邮箱均由开发配置，后续统一提供）。
  5. 列表默认按「导入时间」降序展示（最新导入的任务排在最前）。
- **原型改动（HTML 位置/字段）**：文件 `V3.3.0美赞牧场自动发放返利功能.html`
  - 筛选栏（约 L392）：状态后新增「返利类型」下拉（全部 / 人工调整 / 美赞牧场）。
  - 列表表头（约 L421）：任务编号后新增「返利类型」列。
  - 列表渲染（约 L1400–1430）：每行注入返利类型标签（人工调整=蓝、美赞牧场=橙）；状态逻辑——美赞牧场 + 待执行→「待执行」，人工调整维持 未执行 / 已执行；操作逻辑——美赞牧场 + 待执行→仅「执行」，其余 人工调整 pending→执行+删除、done→空。
  - 示例数据（约 L1379–1396）：原 13 条人工调整任务补 `type:'人工调整'`；新增 2 条 `type:'美赞牧场'` 任务（20260827030000MSP5WX9A / 20260826030000TQ4KZ8XB，状态 待执行、操作仅 执行）。
  - 详情弹窗（约 L1527–1533）：detailData 新增上述 2 条任务的明细，返利名目 = 「POS00000123123-美赞牧场」，门店ID / 门店名称 = 总店信息。
  - 操作栏（约 L402）：新增「新增任务」按钮，弹出新增表单（任务名称 / 返利类型默认 人工调整 且禁用 / 备注），保存仅提示（demo）。
